# 实现补齐与配对结果（2026-11-10）

本文件更新此前“只有接口”的状态；旧运行说明保留历史。当前实现标识为`dependency-contract-v2`。六模块均已接入Flatland执行循环，但实现采用集中消息总线、同步可靠通信和有条件轨迹承诺，不宣称异步分布式协议或形式化安全保证。

## 1. 新增的实际执行能力

| 模块 | 具体落地 |
| --- | --- |
| 承诺期限 | 固定8步对照；完整方法依据有限预测冲突时刻选4–32步条件有效期。执行器执行被接受的路线和等待，而非每步私自重求最短路。 |
| 未来依赖 | 当队友计划未来使用承诺方已让出的轨道格，登记consumer/provider/version/resource/use_at；无需队友已经行动。变化前检查未来使用时刻是否重新占用该资源。 |
| 候选前瞻 | 保持原路线与等待；最多3条合法轨道路由；0/3/8/16步等待；32步占用及对向换位冲突评估。替代路线通过逐边禁用最短路搜索获得，不是全路径枚举。 |
| 消息确认 | 单调版本提案；每个受影响队友根据自身未来路线、使用登记评估；同意才提交。拒绝后尝试下个路线/等待候选，全部拒绝则保留有效旧承诺，否则停止并退避重试。旧版本ACK不能批准新提案。 |
| 局部修复 | 替换、失效、撤销沿provider→consumer注册图递归标记受影响Agent，仅其重新决策；全局修复消融标记所有Agent。 |
| 紧急撤销 | 原生故障或观测轨迹偏离即撤销，不等待许可；停止并传播修复。结束列车显式release。 |

预测区分未发车的无占用状态，考虑最早发车、最高速度和格内进度；未知故障不作为未来输入。预测仍是近似：9–41次偏离撤销说明执行假设并不总成立，不能将其解释为精确动力学MPC。

`Ollama`维护按Agent隔离的短历史；模型可以选择自身候选，也可以对收到的提案选择同意或请求替代窗口。程序对冲突及受损依赖有硬校验，模型不能用一句同意绕过。预算耗尽明确计数规则回退。

## 2. 自动验证

9项单元测试全部通过，覆盖未来依赖、未来清空承诺被修订破坏、递归修复不影响无关Agent、拒绝后版本不复用、过期版本ACK、超时、故障撤销、对向换位冲突、未发车不占轨。

每个run保存源码快照、场景哈希、动作轨迹、提案及队友评估、依赖注册、最终计划和模型原始请求响应。完整消息数包含前瞻候选拒绝、依赖登记及确认，不应只按LLM调用次数宣称通信更少。

## 3. 21局配对结果

汇总：`runs/20261110-092505-paired-suite.json`。同一场景pickle在不同方法间复用，原生故障依赖执行过程，不保证不同策略故障时刻完全一致。每列场景仅一个配置实例，没有统计显著性结论。

| 方法 | Level_0到达 | Level_1到达 | Level_2到达 |
| --- | --- | --- | --- |
| 独立重规划 | 3/7 | 7/7 | 3/7 |
| 固定8步承诺 | 7/7 | 5/7 | 0/7 |
| 完整方法，规则后端 | 7/7 | 7/7 | 7/7 |

| 全局修复替代局部 | 7/7 | 7/7 | 7/7 |

完整规则控制循环约0.09–0.29秒/局，全局修复约1.04–2.07秒/局；包含日志序列化但不含进程启动与环境加载。并行后台任务使时间有噪声，不作为严格速度基准。

完整方法未来依赖注册数分别为7、7、22；局部修复次数2、0、5；执行偏离撤销9、41、19。这里没有把所有暂时停止叫作死锁。

**能说的结论**：此版本完整方法在三个实例均完成，初步优于自带独立及固定期限对照；Level_0的候选前瞻与确认消融下降。

**不能说的结论**：未来依赖模块已被证明有效、LLM优于规则、优于官方强基线、普遍无死锁。未来依赖消融同样7/7，说明当前实例的到达率尚不能辨识该核心贡献，不能隐去该负面证据。

## 6. 尚未冒充完成的事项

- 当前未来依赖语义是未来使用已清空的轨道格，不是任意自然语言任务依赖；时间使用窗目前为离散单步。
- 确认在一个环境步内同步完成，ACK超时已单测但未在延迟/丢包环境验证；替代协商是提案方枚举下一候选，不是自由语言多轮谈判。
- 预测不完整考虑实际动力学；执行监测撤销是保守补救，不是安全或稳定性证明。
- 需要接官方强基线、更多公开配置和配对统计，并设计不改变官方环境的故障/承诺变更诊断来辨识未来依赖价值。
- 暂无“LLM增益”证据；模型可选择但受规则校验，后续必须做同候选同信息规则对照。
