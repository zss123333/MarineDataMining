## 1. 用户确定的研究范围

主平台为开源[Flatland](https://github.com/flatland-association/flatland-rl)。保留完整思想：承诺期限、当前及未来依赖预测、有限候选前瞻、消息确认、局部修复与紧急撤销。它们组成一个闭环，而不是拆成互不相干的六项研究。模块消融用于归因，不是删掉完整方法。

模型使用本机Ollama中的qwen2.5:1.5b，运行前记录digest和量化；每个列车Agent有独立上下文，共享一份模型服务。模型只见允许发布的信息，不直接读其他Agent未发布内部计划。

## 2. Flatland中的语义落地

| 思想组件 | 实现对象 |
| --- | --- |
| 承诺期限 | 在环境步窗口内等待、按公布路线行驶，或预计清空指定共享区段；区分保证动作与预测到达时间 |
| 依赖预测 | 当前执行及后续路径需要他车让行/清空的区段；未进入区段也可能存在未来依赖 |
| 候选前瞻 | 保持原计划、调整等待时间、合法替代路径或申请替代窗口；有限前瞻使用同一模型假设，不读取真实未来故障 |
| 消息确认 | 对具体承诺版本的接受、释放及替代确认；确认不等于列车已经开始移动 |
| 局部修复 | 只调整受故障或承诺变更影响的未执行路线、时间窗口和依赖 |
| 紧急撤销 | 原承诺因故障不可行时声明失效、停止或降级并通知队友；不等待同意才处理不可行性 |

不能保证未知故障下准时清空，因此承诺必须写成立条件与可撤销条件。模型输出意图，代码负责合法轨道动作、版本、期限、消息和证据校验。轨道合法不等于全局无死锁。

## 3. 任务选择：先用现成资源，不自建铁路仿真

使用[官方场景库](https://github.com/flatland-association/flatland-scenarios)中公开竞争场景或对应官方生成器配置。下载或生成的地图、任务、时刻表和故障配置统一放 `expr/datasets/flatland-core/<version>/`，记录上游commit及哈希。现在尚未准备该数据版本。

首先核查小规模场景：双列车或少量列车、共享区段、交汇/等待关系。若从官方大场景抽取双列车，需记录抽取规则并验证实际冲突；不能把抽取变体冒称原样标准benchmark。优先保留原场景，不为本方法专造必胜地图。

选择三类条件：正常可执行（应保持协调）、原生故障或延迟（可能需修订）、存在可替代路线或无需保护的关系（检验过度保守）。未来故障不对方法提前公开；同种子不自动意味着各策略经历同一内生故障，要核对触发语义。

## 4. 模型与控制分工

LLM在进入关键共享区段、收到承诺修订、相关故障、窗口临近或依赖变化时作出元认知和候选选择，不每个移动步推理。低层控制负责将已选择的合法路线/等待计划转换成Flatland动作；常规行进不调用LLM。

先使用结构化区段、可选路线、时间窗口和事实摘要，避免让1.5B直接读整张大地图。候选与可行性信息向各对照方法等量提供。若候选前瞻的规则求解已经决定答案，必须承认模型没有独立增量，不能只让LLM复述结果。

在对外承诺修订前进行完整闭环：更新事实 → 预测当前/未来依赖 → 构造候选 → 前瞻与可行性检查 → 保持/修订/撤销选择 → 必要确认 → 局部修复 → 执行并反馈。

## 5. 强基线与消融

完整方法对比独立事件重规划、固定承诺/预约窗口、规则依赖保护与滚动局部修复，以及[官方deadlock avoidance基线](https://github.com/flatland-association/flatland-baselines)。固定方法不能隐藏拥有更强路径信息或更少执行约束。

消融：只保留当前依赖、不做候选前瞻、无确认协调、全量重规划替代局部修复、固定期限替代动态期限。紧急处理的基本安全能力所有方法都有；消融的是协调撤销与依赖传播，不是故意让基线无法响应故障。

不是一开始跑完整组合爆炸：先完成完整方法和强基线的同协议运行，再按费用与时长预算执行有针对性的模块消融。模块仍全部实现，不以压缩运行矩阵代替完整闭环。

## 6. 指标与后果

主要指标：按期/最终到达率、未完成列车数、环境步延误与任务收益。死锁需有可检查定义：与实际剩余可行推进条件结合，不把故障期间暂时静止自动算死锁。无法严格判定的静止称阻塞/超时，不能冒称不可恢复死锁。

辅助指标：依赖失效、修订恢复步数、额外等待、无效重规划、消息数/字节、模型调用、输入输出token、端到端时长。程序阻止碰撞，因此严重后果描述为全局阻塞和任务失败，不声称模拟发生真实列车事故。

## 7. 安装与数据的当前状态

本轮PyPI核实 flatland-rl 4.3.0，Requires-Python>=3.10，依赖numpy<2，且涉及较多额外包。官网README当前main支持的版本与PyPI发布不一定完全一致，正式运行必须固定发布版和对应场景版本。

不得在系统或已有厨房环境里直接安装并降级NumPy。采用独立环境，并先测reset/step、任务加载、原生故障与参考基线；若存在兼容问题保留错误日志。安装命令、版本与代码要在验证后补入，不在这里假装已跑通。
