# 方案—实现—指标对齐与过程核验

日期：2026-11-10。本轮不按目的地继续拆组，先用七列车共同交通任务核验协调行为。后端为规则，无LLM调用。

## 对齐表

| 方案要求 | 实现 | 可核验指标/日志 |
| --- | --- | --- |
| 具体通行承诺 | 候选公开资源格、绝对进入/退出时刻、承诺版本、有效期限；窗口exit为不包含端点 | messages.json的passage_windows、commitment_version、valid_until |
| B/C自己响应 | response_options返回最多3个本地方案；公开条件和成本，不发送私有路线对象 | respond消息的options；prepare绑定candidate和本地option编号 |
| 冲突不立即放弃 | 提案方按总代价优先尝试响应组合，冲突后继续检查下一组合，每候选最多128组 | negotiation.json的combination_search和combination_found |
| 比较联合代价 | 自身剩余行程/等待增量，加计划变更修复单位代价 | options.delta_cost、repair_cost |
| 确认后近期执行 | 各方prepare核验自身版本，commit安装自己的具体响应，每步执行一个动作 | selected_combination、commit、trajectory.jsonl |
| 修复确实发生 | 已有计划的未来预测变化计1单位修复成本，实际安装才累计 | repair_installs、repair_cost |

## 实际运行

| 场景 | 到达 | 最终提交含替代响应的组合 | 已安装修复次数/单位成本 | 候选级找到替代组合 |

| Level_2 | 7/7 | 5 | 7/7 | 20 |

三个run：`20261110-132849-322484-flatland-distributed`、`20261110-132856-213510-flatland-distributed`、`20261110-132901-297546-flatland-distributed`。墙钟分别约3.89、1.92、3.14秒，消息数854、1121、1310。

候选级替代成功不等于最终选择或提交：本轮另外记录selected_combination，并与同一提案commit配对，避免将46次候选搜索成功描述成46次成功协商执行。最终提交计数表示选用了至少一个非首项本地响应，不保证该提案的首选组合必然冲突；具体冲突重试可查组合检查次数。

17项测试通过。新增三Agent测试让B/C首项响应争用同一时隙，C提供另一时隙；核心确实检查超过一个组合，并选择C的替代项，三个Agent完成提交。该测试验证机制，真实环境日志验证机制进入执行流程，不是仅新增未调用接口。

## 与上一版比较的边界

上一版单响应单交通组为6/7、7/7、7/7；本轮均7/7。但同时引入修复代价与多响应菜单，且故障可能随执行改变，因此不能将所有收益直接归因于单一模块。需要冻结版本进行同信息单响应消融后再作因果结论。

## 明确限制

- 目前为“一次交换多个响应，再进行有界组合搜索”，不是发起方给出新约束后让队友多轮重新求解。它已经避免首项冲突就拒绝，但不冒充完整迭代分布式优化。
- 提案方只搜索公开报价的组合，不替队友生成私有计划；存在临时协调者及有界组合搜索，不宣称无协调者或全局最优。
- 128组搜索上限可能漏解；最多3项菜单可能丢失有价值的后续响应。主项不可行而替代项可行的菜单目前尚未为通用任务全面验证。
- 时间窗目前由精确到格的近似占用序列展开，不是区间弹性约束求解器。未知故障下只提供条件承诺。
- 修复成本为显式设计的单位代理量，不是实际CPU秒、token或现实经济损失；通信成本单独记录，尚未进入总代价目标。
- 没有重跑目的地分组，也没有声称当前解决了分组失败、减少通信或证明LLM增益。
