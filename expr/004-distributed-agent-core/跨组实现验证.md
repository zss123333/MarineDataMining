# 跨组核心实现验证

日期：2026-11-10。规范代码为`../../核心源码/agent.py`，实验入口继续兼容导入，不维护第二份核心。

## 本轮实现

1. 本地Task通过`coordination_peers`报告需要征询的直接依赖；普通提案从绑定任务组开始。
2. 新成员触发旧提案abort，使用新提案键扩大范围并重新响应、准备和提交；旧确认不能用于新版本。
3. 各成员仅报告自身增量代价，消息绑定cost_owner；提案方按身份汇总代价，防止重复响应重复计费，不允许B把D的代价计入自己后再加入D报价。
4. 准备锁拒绝重叠提案，执行屏障禁止在未完成准备提交时动作；状态变化在prepare阶段重新检查。
5. 紧急撤销通知本组及本地登记的跨组直接依赖方，收到撤销可取消相关未完成提案。

## 实际验证

12项测试通过。六成员场景中：A/B/C为原任务组，B声明依赖D，D声明依赖E，F无关联。最终仅A/B/C/D/E参与提交，F没有收到任何消息；扩展过程出现多个不同提案键，旧提案不能直接完成新范围确认。

其他测试覆盖循环依赖不无限扩展、准备锁冲突、准备期间不能执行、原有本地版本失效、重放、组内隔离及三Agent总代价选择。原三Agent演示仍返回三者joint、15条消息。

## 边界

这是显式扩大参与范围，不是嵌套子组代表报价；必要时相关成员可能最终覆盖全网，但不会无条件全网广播。所有新增成员必须由现有参与者明确声明依赖。

每实例仍绑定一个任务组；允许跨组依赖方加入本次提案，但尚未提供同一身份的多实例共享状态、多进程网络运输、提交阶段故障恢复或无饥饿保证。可靠同步协商并冻结状态仍是前提。

这轮完成的是分布式核心协议，不是Flatland任务适配或新效果实验。Task仍需真实实现响应、依赖登记、承诺期限与近期动作，才能接入具体任务；不能把协议测试当成方法效果证据。
