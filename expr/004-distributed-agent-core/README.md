## 参考ReAct的方式

参考[ReAct官方仓库](https://github.com/ysymyth/ReAct)及其[HotpotQA示例](https://github.com/ysymyth/ReAct/blob/master/hotpotqa.ipynb)的`webthink`：在统一循环内决策、执行动作、接收观察，并将反馈用于下轮。本实现借鉴循环与任务解耦的结构，不复制代码，也不声称ReAct原实现已经是分布式MPC。

这里的消息也是行动：Observe → Propose/Respond → Prepare/Commit → Execute prefix → Observe。模型生成的是结构化候选、响应和决策摘要，不要求暴露私有推理。

## 核心代码在哪里

`src/agent.py`中的`run_agent`是最外层循环，`Agent.think`是所有Agent共用的协议状态机，`Task`定义可插拔任务能力。

```python
def run_agent(agent, clock):
    while not clock.finished():
        agent.step(clock.round())
        clock.exchange(agent)
        clock.execute(agent.identity, agent.act())
```

该循环内，每个Agent执行相同规则：

1. 本地观测不可行时立即撤销、通知队友；需要改计划时公布候选，不能立即执行新计划。
2. 收到提案后，针对每个候选调用自己的`task.respond`，给出自己的响应计划、可行性、公开条件和增量代价。
3. 仅发送可行性、公开条件和代价；响应计划留在各自`local`，A不读取B/C内部计划，也不替它们预测响应。
4. 轮到的提案方汇总响应，检查公开条件能否共同成立，选择总代价最低的可行组合。
5. 每个Agent再次核验自己的本地版本，全部ready才提交；任何不满足则abort并保留旧计划。
6. 每个Agent安装自己的响应计划，任务执行器只执行近期前缀，再获取反馈。

## 分布式边界

- 无固定中央规划Agent。提案权按公开成员顺序轮换，A/B/C均可发起，运行同一代码。
- 一轮只允许一个发起方，避免并发提案修改同一承诺。它是同步协调的串行化假设，不是异步并行协商。
- 临时发起方汇总当前提案的公开报价，是提案级协调角色，不拥有其他Agent的规划器或私有计划。它不等同于完全无协调者算法。
- 所有成员都回应，使C不因只考虑A/B而被遗漏；当前消息开销随成员数和候选数增长，不宣称可扩展性已验证。
- 中央进程可以模拟消息及同步时钟，但不得替Agent选择响应或做联合规划。真实多进程/网络运输只需替换Transport和Clock，目前未实测。
- `Clock.exchange`必须完成同步消息阶段再执行环境动作。ready到commit的区间冻结任务状态；不允许故障或独立执行悄悄改变已准备状态。跨故障原子提交不在当前假设内。

## Task插拔接口

| 接口 | 职责 |
| --- | --- |
| observe / needs_revision | 本地观测与是否值得重规划 |
| candidates | 包含保持原计划的有限候选，公开影响范围、期限和条件 |
| respond | 本Agent对候选的有限前瞻与局部修复，返回自己的方案与增量代价 |
| compatible | 仅基于公开条件检验响应组合是否一致，不能私读队友状态 |
| valid / install | 本地版本再核验与安装已确认响应 |
| infeasible / revoke / dependency_changed | 条件失效、紧急停止及依赖修复触发 |
| act | 执行自身计划近期前缀，不执行整个预测时域 |

报价必须使用一致代价口径，并相对于各自保持方案计算；资源冲突等不可接受条件应标记不可行，而非靠低罚分掩盖。可将LLM封装进候选生成和本地响应，但协议校验不依赖LLM自由文本。

六模块并未被删减：期限和未来依赖属于候选/本地计划语义，前瞻与修复由各自respond实现，确认与撤销由核心状态机承载。核心不伪装自己能在无任务模型时计算路径或识别依赖。
