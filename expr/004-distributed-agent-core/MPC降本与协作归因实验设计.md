# MPC降本与协作归因实验设计

2026-11-12。设计稿，尚未执行。来自[方案中的MPC效率设计](../../创新方案设计.md)与[Stronger-MAS实验借鉴](../../参考文献/多agent协作/StrongerMAS实验方法借鉴.md)。不训练新模型，不改地图使方法获胜。

## 1. 先检查“为什么花钱”，再改算法

在现有开发实例上加分项计时：路线生成、预测、响应、组合检查、消息编码、LLM推理和环境推进。记录调用次数和缓存命中。以完整方法为基准，先确认重复生成、消息体积和组合检查分别占多少，不能只看整局墙钟猜瓶颈。

## 2. 固定规划器，比较五种协调设置

| 设置 | 保持相同 | 唯一主要变化 |
| --- | --- | --- |
| A 独立规划 | 地图、初态、候选工具和模型 | 不征询队友 |
| B 单响应 | 同上及确认流程 | 每个队友只提供一个配合办法 |
| C 当前完整方法 | 同上 | 提前生成最多3响应，完整组合检查 |
| D 复用版本 | 与C相同的候选空间和约束 | 复用路线、预测、仍有效响应，先不改触发条件 |
| E 依赖触发与有限前瞻 | 与D相同的任务目标和约束 | 仅在相互影响时通信，只协调共享约束成员，执行到需要反馈的位置再调整 |

D先验证只省重复计算是否保持决策一致；若不一致，应检查缓存失效错误，不把性能变化自动归为收益。E改变决策与可达选项时序，需单独衡量质量，不与D混在一次修改中。

## 3. 两层公平性

端到端：同地图、初态和信息权限，同模型版本、温度、工具、调用上限及超时。报告实际消耗，不能只说上限相同。协调消息自然不同，后续轨迹也会不同。

同节点归因：保存环境、随机数、故障、所有成员本地计划、承诺版本、缓存与模型上下文，在完整快照处分支运行B/C/E。控制所获外部信息和额外工具预算，比较接下来固定窗口和最终任务结果。不能用现有只重放位置的脚本冒充完整快照。

## 4. 数据与失败

旧v1、v2-audit以及已查看的v3-holdout可作开发诊断，不再当未见保留数据。完成降本实现与配置冻结后，再预先固定一批新种子作保留集，并保存生成参数、SHA256与所有方法运行清单。不同种子生成不等于自动无重复，需要地图、时刻表和初态联合去重。

保留正常、共享资源竞争及原生故障实例，报告实际触发。若需要严格同故障反事实，另设以环境时钟索引的外生故障实验，并明确它不是原生执行相关故障机制。不同故障条件分别报告，不能混为同一比较。

## 5. 指标与停止条件

- 任务：到达比例、严重失败、惩罚完成时间；失败不能从延迟统计剔除。
- 协调：协商次数、每轮人数、消息轮数、额外响应触发率、候选和组合检查。
- 成本：消息序列化字节、实际输入输出token、LLM及工具次数、分项墙钟。
- 行为：撤销后到再次安装与到正常前进分别计时；8步内重复修复只作现象，反事实不改仍可完成才支持“不必要”的判断。
- 不确定性：按独立场景做配对差值和区间；不把7个同场景Agent当7个独立样本。重复计时区分冷启动、热模型和机器负载。

在开发集选少量预先规定的前瞻窗口与执行边界配置，画任务质量—成本曲线。只有同等质量下成本下降，或增加少量成本换来明确实际收益，才称高效。若D不能保持正确性或E不能改善质量成本取舍，停止扩展，而不是反复修改窗口查看保留结果。
