# 面向多 LLM Agent 协作的依赖感知承诺元认知

> 方案版本：v1.1，2026-11-09。状态：待实现、待实验验证。本次修订：依赖评估覆盖正在执行、已规划但尚未执行，以及有限时域内可合理预见的未来依赖，不以“队友已经开始行动”为前提。目标是在不训练基础模型、不引入机器人硬件的条件下，尽快完成一篇具有可辨识设计贡献与可靠实验的论文。本文是设计方案，不是已完成实验报告；“新颖性”是当前文献范围内的研究假设，不宣称全球首次。

## 一、选题与核心主张

### 1.1 暂定题目

中文：**面向滚动规划多智能体的依赖感知承诺元认知方法**。

英文：**Dependency-Aware Commitment Metacognition for Receding-Horizon LLM Agents**。

方法暂称 DACM，仅作为项目内部名称，不暗示名称已经查重。

### 1.2 一句话说明我们做什么

**让 LLM Agent 在改变计划之前，前瞻判断队友当前与未来哪些行动将依赖自己的承诺，以及这次改变会如何影响这些行动的可行性与时序；据此选择继续履约、在承诺范围内调整，或提前协调修订。**

核心不是预测回答长度、学习一个重规划间隔，也不是给 Agent 接一个 MPC 求解器。我们把 MPC 的“滚动前瞻—执行局部—反馈更新—保持约束”思想内化为 Agent 的认知循环；其中的约束包含队友正在依赖的对外承诺。

### 1.3 为速度主动缩小范围

第一版仅研究合作型、共享目标、可信参与者的两个 LLM Agent。环境可观测状态与工具结果由程序提供，允许通信，但要计入成本。暂不研究恶意承诺、经济激励、自然语言博弈、模型训练、真实机器人、连续控制或完整控制理论证明。

采用结构化承诺对象，暂不把几何警告带作为必要模块。它可作为未来空间任务的可视化实现，但“带宽变大”等于“承诺变长”的映射并不天然成立。本文也不声称无需通信。

## 二、问题究竟是什么

### 2.1 一个最小例子

在协作厨房中，A 承诺接下来准备并放置盘子，B 当前仍在拿洋葱，但计划稍后出锅与交付，届时需要 A 的盘子。中途 A 观察到新的机会，重新规划去拿洋葱。该选择对 A 的局部计划可能有利，却会使 B 尚未开始的后续步骤失去前提；即使 B 还没明确安排出锅，根据共享任务与可见进度，也可能合理预见这一需求。

我们希望 A 不仅判断“换任务是否更好”，还判断“B 接下来可能怎样行动、何时需要我的交付，以及我的改变会不会堵住这些未来安排”。队友尚未行动、未发确认，都不等于不存在依赖。A 应基于共享计划、可见状态和队友消息进行有限时域前瞻；对已明确的未来依赖进行协调，对不确定但影响较大的潜在依赖先询问或提供替代，而不是等到对方已经受阻才补救。

这不是假定必须出现振荡。可能观察到的失败包括等待、重复劳动、交接落空、级联修复和无效 LLM 调用。“承诺振荡”只是一类可检验现象，不能预设为必然。

### 2.2 三个量必须分开

| 概念 | 定义 | 在本方案中的处理 |
| --- | --- | --- |
| 规划时域 H | 内部向前规划多远 | 第一版固定有限宏动作长度，避免同时优化多个变量 |
| 开环执行长度 k | 两次内部重规划之间执行多少动作 | 各比较方法采用一致的检查机会；不是唯一创新变量 |
| 对外承诺有效期 T | 在什么条件和期限内保持哪些可依赖性质 | 核心管理对象；允许内部计划变化而对外性质不变 |

例如 A 可以在内部重排路线，却仍按期提供盘子；这不算违约。内部重规划频率高，不自动等于对外不可靠。承诺有效期以环境步数或宏动作里程碑表示，不用 LLM 调用墙钟时间混充。

### 候选设计贡献

1. **认知对象**：把“别人现在及接下来会依赖我的什么、何时依赖、依据有多充分”加入 Agent 的显式元认知状态，而非只维护自身置信度。
2. **更新规则**：将内部重规划与外部承诺修订解耦；保护仍有效的确定依赖，包括尚未执行的计划依赖，并对预测性依赖按证据、影响与时间窗口处理。
3. **决策动作**：让 Agent 在保持、等价调整、请求修订、紧急撤销间选择，结合小规模候选前瞻评价下游影响。

这三项须形成可运行的方法，而非三个新名词。版本号、确认消息和依赖图属于成熟技术，不单独申报为创新。后续仍需补查社会承诺、Joint Intentions/SharedPlans、协作计划修复及 LLM 承诺协调近邻；现有五篇不足以穷尽文献。

## 四、总体架构：Agent 自己管理承诺

```text
环境观察 / 工具返回 / 队友消息
              ↓
更新局部任务状态、承诺账本和依赖证据
              ↓
快速检查：承诺到期？外部失效？计划变更？
              ↓ 必要时
LLM 元认知：谁依赖我？依赖依据是什么？改变会影响什么？
              ↓
生成少量候选 → 有限前瞻 → 约束检查 → 选择修订动作
              ↓
保持 / 承诺内调整 / 协商修订 / 紧急撤销
              ↓
执行有限宏动作，接收反馈，滚动更新
```

低层执行器负责合法工具调用和宏动作落实；通信层负责投递消息、版本去重和日志；它们不代替 LLM 选择任务与修订方案。**若所有选择最终都由规则完成，论文应定位为协调协议，不再声称具有 LLM 元认知贡献。**

### 4.1 承诺对象

每个承诺包含：

| 字段 | 用途 |
| --- | --- |
| commitment_id、version、owner | 标识承诺及其发布者 |
| deliverable | 可观察交付结果，如将指定物品放到指定位置 |
| validity_conditions | 承诺成立的前提及失效证据 |
| expiry_step | 期限或最晚交付步数 |
| allowed_changes | 不改变交付性质的内部调整范围 |
| status | proposed、active、fulfilled、expired、revoked |
| evidence | 当前判断引用的环境事实与消息 ID |

承诺尽量描述“结果与条件”，而非锁住所有原始动作。交付必须能由环境或工具日志检查；无法自动判定的自然语言承诺暂不进入主实验。

### 4.2 依赖对象：区分执行依赖、计划依赖与预测依赖

Agent 在接收队友承诺后，由 LLM 判断自身当前与后续动作何时需要该交付；发布者也根据共享计划、队友进度和任务结构主动预测未来依赖，不等待对方先开始行动或发来确认。返回承诺版本、依赖动作、预计使用窗口、必要条件和证据。程序验证引用是否存在、字段是否完整，不替 LLM凭空创造语义关系。

| 依赖类别 | 判定依据 | 处理原则 |
| --- | --- | --- |
| 执行依赖 | 当前动作或已发生的投入需要该承诺 | 检查即时可行性，避免破坏进行中的协作 |
| 计划依赖 | 明确的后续计划需要该交付，动作尚未开始 | 同样纳入承诺约束，不等待执行后才保护 |
| 预测依赖 | 根据任务结构、观察与可能计划推断的未来需求 | 记录证据与不确定性；高影响时询问或预留替代，不把所有猜测一律硬冻结 |

显式确认表示“我的当前或未来安排使用你这一版承诺”，既不是“已经开始行动”，也不是依赖存在的唯一证据。无确认时仍须检查预测风险；不能假定队友的不可见计划已被准确获知。第一版只支持基于结构化任务、工具和对象实体的依赖判断，避免无限自然语言理解问题。

依赖记录包含 consumer、producer_commitment_id、producer_version、dependent_step、dependency_type、expected_use_window、evidence_source、uncertainty、status。预测置信度未经校准时只作定性等级，不伪装成可靠概率。每次滚动更新依赖窗口和证据；动作完成、依赖被替代、到期或失败后清理，避免陈旧预测永久锁住计划。时域外需求作为边界风险或后续任务摘要保留，不声称有限前瞻覆盖全部未来。

### 4.3 元认知调用的最小输出

不要求输出自由长篇思维链，只输出可核查决策摘要：

```json
{
  "referenced_commitments": ["A-c3-v2"],
  "affected_dependents": ["B-step4"],
  "evidence_ids": ["message-17", "observation-29"],
  "decision": "request_revision",
  "replacement_deliverable": "plate_at_counter_2",
  "replacement_expiry_step": 40
}
```

schema 约束与对象存在性可机械检查；“改动是否真正等价”仍需环境判定或任务语义验证。不能用结构化 JSON 合法性冒充推理正确性。

## 五、滚动决策与承诺修订

### 5.1 哪些时刻需要思考

不增加一个每帧 LLM 反思器。便宜规则每步检查：相关工具失败、承诺条件变化、交付期限临近、队友请求修订、准备切换当前子目标。出现事件后才调用元认知；正常执行按既有计划推进。

所有方法获得相同观察和事件，LLM 推理预算设上限，实际使用量计入成本。外部环境事件不等于承诺被 Agent 主动破坏，日志要分原因。

### 5.2 四种决策动作

| 动作 | 适用条件 | 对外效果 |
| --- | --- | --- |
| KEEP | 旧承诺可行且变更收益不足 | 维持原结果与期限 |
| ADJUST_WITHIN | 内部修改不破坏有效承诺 | 路线或局部顺序改变，外部交付性质保持 |
| REQUEST_REVISION | 必须改变被依赖交付，且仍可等待协调 | 提供替代结果/期限，通知受影响方 |
| EMERGENCY_REVOKE | 环境已使原承诺不可执行或存在硬风险 | 立即安全停止/降级并广播失效，不等待同意才避险 |

元认知不是默认延长承诺。更长承诺有时稳定协作，有时延续错误；必须由任务收益、依赖影响和可行性共同决定。

### 5.3 有限候选前瞻：MPC 思想的具体落点

第一版在事件时最多评估三类候选：保持原安排、在承诺内局部调整、提出一个替代承诺。紧急不可行直接走撤销，不强行保留旧计划。规划仅覆盖接下来若干宏动作，而不是仿真无限未来。

候选评价至少含：任务进展、可执行性、队友当前及未来依赖的失效风险、等待代价、消息与 LLM 开销。对各候选检查：在预计使用窗口内是否仍能交付，是否使后续关键步骤不可行，是否存在替代资源或可接受的时间调整。预测依赖可用少量合理后续场景评估，不能将未经校准的 LLM 置信度直接当概率计算精确期望。使用程序可得状态计算精确项，LLM 提供有证据的语义依赖与有限候选，不让其凭空断言环境真实未来。

可采用以下设计目标表达折中：

J(candidate)=任务代价+λ_dep×受影响依赖+λ_wait×等待代价+λ_compute×额外计算代价。

权重只在开发集设定并冻结，先采用少量离散候选和规则化排序，不训练价值模型。环境安全、工具权限、资源互斥等硬约束先筛选，不靠有限惩罚权重保证安全。该目标是决策设计，不提供控制稳定性结论。

### 5.4 修订协议的最小语义

1. 先检查执行、计划与预测依赖。仅在没有有效确定依赖，且有限前瞻未发现需协调的未来风险时，允许直接更新版本并广播；“未开始行动”或“未收到确认”不是直接更新的充分条件。
2. 对执行依赖或明确的未来计划依赖提出 replacement；旧承诺在仍可行时保持，受影响方确认释放旧依赖或迁移到新版后，再正式切换。预测依赖按影响决定先询问、提供替代或带风险更新，不将所有可能性都升级成无限等待。
3. 确认指向具体版本，旧确认不能激活新承诺；重复消息幂等处理。
4. 协调等待超过限定步数后，执行任务允许的安全降级：暂停相关动作、撤回依赖、重新分配。不能假装超时后自动履约，也不允许无限等待。
5. 若旧承诺已外部失效，立即发撤销并进入修复；不声称消息尚未送达期间系统仍绝对一致。

第一阶段使用可靠即时投递，之后加入有界延迟；丢包与 Byzantine 行为不作为首版贡献。协议中的等待图需检查环，出现循环修订时用固定 Agent ID 优先级解除对称等待；同样提供给适用基线，避免把一个隐藏仲裁规则算成元认知收益。

### 5.5 一次迭代的伪流程

```text
获取本 Agent 观察与收到的消息
清理已完成、已过期或已被替代的依赖
检查是否存在相关失效或计划变更事件
若无事件且当前动作可执行：继续执行有限动作
否则：
    用相同可用证据调用 Agent 元认知
    产生保持、承诺内调整、替代承诺候选
    检查硬约束、有效依赖与修订条件
    在可行候选中选择一个有限时域方案
    必要时通知受影响方并等待有限确认
    若不存在可行候选：撤销、降级或记录任务失败
执行有限宏动作并记录实际交付和队友影响
```

## 六、实验环境与最小实现

### 6.1 主环境：优先验证 Overcooked 可复用性

首选公开 Overcooked-AI：有协作分工、资源交接和等待，且与 SyncPlan 存在共同任务背景。先检查公开环境、低层宏动作、自动指标是否能稳定运行，再冻结实际版本、地图文件、episode horizon 与种子。

先选两张公开布局：一张交接依赖较强，一张依赖较弱；只在实际代码中核实可用后确定名称，不把论文里三张布局视为本地必然可用。低层宏动作执行器在所有方法中共用，避免让路径规划差异决定结果。

若宏动作适配成本明显失控，先用已有离散共享资源/任务执行环境验证核心闭环，明确它是受控实验；不能为了快速而仅靠专门为本方法构造的玩具场景就宣称普适有效。暂不依赖 HoK 接口或 SyncPlan 未确认公开的训练数据。

### 6.2 四类条件

| 条件 | 检验目的 |
| --- | --- |
| 无外部扰动 | 方法是否无谓增加通信、保守等待和推理成本 |
| 局部资源/工具失效 | 能否定位受影响承诺，而不是全队重规划 |
| 队友进度延迟 | 是否减少交接落空与级联更新 |
| 新机会或任务优先级变化 | 是否在保留合理承诺与适应新需求之间折中 |

扰动必须独立于方法触发，不能只在本方法正好可以检测的位置注入。动作相关事件用相同语义规则和预生成随机流，而非简单同一墙钟时刻；不同策略状态不同时，记录事件是否适用，避免产生虚假配对。

### 6.3 第一轮不训练模型

使用一个固定版本、可负担且支持结构化输出的 LLM；运行前记录准确模型 ID、服务版本、temperature、top_p、最大输出、重试策略、超时与价格。当前不凭空指定某家模型一定可用。

规划、元认知和基线共用骨干及上下文信息。解码优先低随机性；即使 temperature=0，远程推理仍可能不完全确定，因此保留多次运行和缓存规则。第二模型只用于主效应成立后的稳健性验证，不一开始铺满模型矩阵。

## 七、基线与消融：必须排除什么解释

### 7.1 最低基线集合

| 编号 | 方法 | 排除的替代解释 |
| --- | --- | --- |
| B1 | 固定周期独立重规划 | 收益是否仅来自不那么频繁改计划 |
| B2 | 同事件触发的独立重规划 | 收益是否仅来自事件触发 |
| B3 | 简单共享计划/承诺期限+修订通知 | 一个标量期限及通信是否已足够 |
| B4 | 规则依赖保护+局部修复 | 是否不需要 LLM 元认知就能实现同样收益 |
| B5 | 相同自检预算的单体有效性检查+通知 | 关键是自身自纠错，还是考虑队友依赖 |
| Ours | 依赖感知元认知+选择性承诺修订 | 检验完整设计 |

另可实现 SyncPlan-inspired 中央行动链+wait+失效触发作为架构对照。但若未使用原模型、PSD及训练，必须明确称“受启发重实现”，不能冒称已复现完整 SyncPlan。FCPAgent 不宜直接挪网页框架跑厨房再声称公平对比，采用明确标注的自检思想基线。

### 7.2 公平性约束

- 环境、任务实例、模型骨干、宏动作执行器、可获得观察一致。
- 各方法可使用同一消息通道与结构化公共事实，不能只给本方法额外真实状态。
- 既报告固定预算下的性能，也报告实际 token、消息、时延；成本不靠人为补齐空调用伪装相等。
- LLM 判断依赖与规则依赖基线采用相同事实输入。可额外用环境真值依赖图作 oracle 上界，但不能给主方法独享 oracle。
- 确认、仲裁、超时和校验器哪些共享、哪些为被测模块须列清单。

### 7.3 核心消融

去队友依赖判断，只保留自身可行性；只考虑已开始的动作，去掉未来计划与预测依赖；去选择性保护而全部冻结；去对外履约约束而仅发送解释；去有限前瞻，仅采用同样信息的贪心修订。优先比较“仅当前依赖”和“当前+未来依赖”，以及 B4，直接检验前瞻而非事后修复的价值。

增加一个配对条件：A 改计划时 B 尚未开始依赖动作，但在后续若干步会需要原交付。分别提供明确共享后续计划与仅有任务/进度证据两种信息条件，检验已知未来依赖维护和不确定未来需求预测；环境真值仅用于评测，不偷偷提供给本方法。另构造预期需求最终未发生的条件，测错误预测带来的过度等待，不能只测保护成功的例子。

## 八、指标、判定与统计

### 8.1 主次指标

**主要任务指标**：固定环境步数内的交付量/任务收益。若采用单目标任务，则用任务成功率；在主实验冻结前选定，不事后选择最有利指标。

**主要协作指标**：每 episode 的实际依赖失效次数，包括当前动作受阻，以及尚未执行的既定后续动作因原交付失效而不可执行或被迫替换；并区分主动换计划、外部不可行、消息延迟三种原因。不能以收到确认或已经开始动作作为统计门槛。仅版本改变、正常重规划或双方接受的等价替换不算依赖失败。

**前瞻辅助指标**：从识别风险到原预计使用窗口的提前量、未来交接实际受阻率、为未发生需求造成的额外等待/机会损失。预测依赖准确性需使用冻结的参考计划或独立标注；经干预后未发生的失败不能直接当作“预测错误”，未尝试的替代策略也不能假称具有可观测反事实真值。

**成本与辅助指标**：输入/输出/缓存 token、LLM 调用数、请求失败与重试、消息数及字节、端到端时间、交接等待、重复劳动、死锁/超时、完成时间。等待与失败均用环境步计，API 墙钟另记。失败 episode 不从成本与平均时间中静默剔除。

### 8.2 避免指标自证

所有方法日志统一映射为同一依赖/交接事件判定；不能只给本方法登记承诺，从而让其他方法“没有违约”。没有承诺对象的基线依据其公开分工与任务前提判定交接失效，单独报告映射口径。主张主要依靠任务结果与成本，而非专为本方法定义的内部计数。

另抽样人工核查元认知引用的证据、依赖判断与修订动作。若用 LLM judge 仅作辅助，不以同一个 Agent 自评替代环境指标。

### 8.3 样本与统计计划

开发阶段只用独立的小批任务调试，不参与最终结果。建议预实验先用一张布局、两类扰动、10个环境种子，识别量级和失败原因，不把它当发表级证据。

正式首批建议两张布局×四类条件×20个环境种子，即160个配对环境配置/方法；先按预算评估是否可承受。随机解码存在时，对配置追加独立重复，并明确“环境配置数”与“LLM运行数”不同。160并非统计功效保证；依据预实验方差、最小有意义效果与预算调整，并在最终测试前冻结。

报告配对差异、95%置信区间及成本—收益曲线。bootstrap 以环境配置为抽样单位，对重复运行分层或先聚合，不能把同一轨迹的每个动作当独立样本。主要比较优先 Ours 对最强简单基线，次要多重比较需校正或明确探索性。报告负结果和各扰动强度，避免只给总体平均掩盖常规条件退化。

## 九、最快成文的推进顺序与止损

| 阶段 | 最小产物 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0：边界确认 | 补查直接近邻；冻结题目与主假设 | 没有发现同设定同核心方法已被覆盖，或能明确实质差异 |
| P1：环境与基线 | 可运行宏动作、日志、B2/B3 | 同环境同种子能稳定评测，不先扩模型 |
| P2：核心验证 | 最小 DACM 与规则 B4 | 相较简单期限与规则保护有可重复净收益 |
| P3：完整实验 | 正式配置、核心消融、成本统计 | 改善不是靠更多通信、额外真实信息或牺牲正常任务 |
| P4：论文与复现 | 代码、配置、图表、论文 | 引用及工件齐全，再按目标期刊投稿 |

不预先承诺若干周必定录用。主要时间风险是环境适配、API成本和强基线失败，而非文字写作速度。

**必须止损或改写主张的情形：**

1. B3/B4 已达到同等效果：撤回“LLM 元认知必要”主张，不继续堆模块。
2. 效果仅来自更多 LLM 调用或更多消息：重新做预算匹配，仍无净收益则停止当前设计。
3. 只减少违约却明显损害任务收益：说明过度保守，不能宣称整体更好。
4. 只在人工专门构造的极端事件中有效：缩小结论，增加自然延迟或常规任务验证。
5. 外部不可行占全部失效：重新检查承诺定义和任务，而非宣称协议保证履约。

## 十、论文叙事与投递

### 10.1 预期论文结构

问题：独立反思可能破坏队友已采用的安排 → 设计：依赖状态进入元认知，内部更新与对外承诺分离 → 方法：有限前瞻与选择性修订 → 实验：任务、协作、成本三方面，特别比较简单协议与规则依赖保护 → 局限：可信合作、小规模、结构化可验证交付与通信假设。

不使用“现有方法在原理上不可能处理”“首次发现承诺属于团队”“无需通信”等超出证据的表述。没有训练也不降低方法门槛，仍须证明设计有不可替代的增量价值。

### 10.2 速度优先投稿策略

沿用[期刊周期核查](参考文献/MPC-Agent新颖性排查与投稿期刊建议.md)的条件性建议：IEEE Access 暂定主投，前提为单位认可、APC可接受和正式实验通过。其官方4–6周投稿至出版为目标，不是录用保证；官方典型录用率约20%，不能当容易录用。费用和政策以实际投稿时复核为准。

Applied Intelligence 为范围备选，不视为已确认更快。最终投递应依据结果形态决定，不为了期刊承诺反向制造正结果，不一稿多投。
