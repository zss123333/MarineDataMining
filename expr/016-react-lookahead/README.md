# ReAct式循环与显式未来计划：开发预试

核心问题回到有限前瞻，不再用通信降本替代规划效果。论文ReAct不禁止多步思考；本目录react是使用同一工具的ReAct式结构化决策适配，不是官方论文代码或原任务复现。lookahead输出最多3项future_plan，每次只执行首项并观察实际反馈。双方均有简短决策摘要、完整历史、相同模型与客户端预算，没有规则替代答案。

固定worker职责为准备和发布报告，工具封装inspect/draft/publish/wait，包含直接发布与必须审阅两种条件；draft消耗原始材料，事后不能补审阅。两个案例是接口及机制开发用例，不是公开复杂任务基准，也不是多Agent实验。复用ToolRuntime的一步工具回执，不让模型产生底层操作语法。

预试102100缺少显式draft_completed观测，且action和future_plan首项可冲突，保留失败记录。修正观测并将前瞻首项作为唯一动作来源后，102236批次：direct中react成功（4次调用，含1次重复draft拒绝），lookahead失败（6次调用）；review中双方均失败（各6次）。前瞻反复输出inspect,draft,publish，导致每次只检查不推进；review后期又转为wait。react则在draft完成后反复重试draft。所有结果均保留模型原文、简短摘要、工具反馈及源码。

这一结果不支持显式前瞻更优；也不证明所有前瞻方法无效。当前只是提示与结构化未来计划，没有计划进度游标、保留有效后缀、分支评估或可执行性模拟。下一步应明确实现滚动计划维护，区分计划延续与必要重规划，并与同预算ReAct式适配比较。不得把少数开发用例包装为ReAct论文基线或优化已成功。

运行：使用014环境python执行本目录run.py；unittest discover -s本目录验证3项状态机测试。每方法每案例一次、温度0、最多6次决策；不是统计重复。模型Qwen2.5-1.5B，token记录于results.json，前瞻更长输出不视为免费计算。
