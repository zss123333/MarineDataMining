# 统一数据集目录

**所有实验数据统一放在此处，不在各实验目录重复下载或复制。** 当前已准备实验001的小规模冒烟输入；不代表正式评测数据已经冻结。实验组织规范见[上级说明](../README.md)。

## 1. 命名与结构

采用 `<dataset_name>/<version>/`，例如未来可建立 `overcooked-coordination/v1/`。仅为命名示例，不表示已有该数据集。

每个版本应包含来源与构建说明、文件清单、原始输入、预处理输入及冻结划分。没有某一类文件时可不建对应目录，说明原因即可。共享输入放这里，运行日志和交互轨迹默认留在所属实验的 `runs/`。

## 2. 版本 README 必填项

| 项目 | 内容 |
| --- | --- |
| 来源 | 官方链接、下载日期；合成数据写生成器与生成配置 |
| 授权 | 许可证、再分发及使用限制；未知时明确标注待核实 |
| 版本 | 上游版本/commit、本地版本、环境及生成脚本版本 |
| 内容 | 文件用途、字段、单位、任务数量、布局及扰动条件 |
| 划分 | 开发/测试任务ID、种子、排重与泄漏检查规则 |
| 构建 | 原始输入、处理步骤、执行位置及实际可用命令 |
| 校验 | 文件大小、SHA-256、生成时间和必要完整性检查 |
| 使用 | 引用它的实验编号、读取方式及依赖 |
| 限制 | 缺失项、外部API变化、快照不完整和复现风险 |

## 3. manifest 与不可变性

`manifest.json` 建议记录数据集名、版本、来源、许可证、生成代码版本，以及各文件的相对路径、用途、大小和 SHA-256。不要填不存在的样本数、占位哈希或假下载地址。

原始数据只读保留。预处理、任务协议或测试划分改变时生成新版本；不同版本可以使用有记录的派生引用，避免复制大型不变文件，但必须能完整定位输入。旧实验固定引用旧版本，不让“更新数据”悄悄改变历史结果。

## 4. Overcooked 输入的特殊说明

交互环境的输入不一定是训练表格。地图、初始状态、任务目标、episode上限、扰动规则、预生成随机序列和开发/测试任务清单，都需要记录。环境源码版本写进数据说明及运行记录，源码本身按依赖管理，不混作数据文件。

同一随机种子不保证不同方法实际遇到相同事件；动作相关扰动还要说明触发条件和不适用事件的处理。测试输入必须在正式比较前冻结。
