## 核心支持到什么程度

支持同构Agent、本地响应、公开组合、参与者扩展、准备提交、撤销、反馈边界、依赖记录、缓存及差量消息等机制。核心不能自行确定铁路中的真实影响范围或生成最优修复；这些须由任务适配器实现。因此“核心支持思想”不等于“完整思想已经在本实验验证”。

本版接入固定路线、变更时间窗、同步协商、到期停止、固定事件表和有限反馈轮次。没有接入精确任务依赖登记、内部无影响更新、差量响应及跨轮缓存；不把未启用功能写作降本贡献。当前反馈约束只用于增加响应覆盖，不是完整冲突区间约束反馈，后续需改进。

## 数据已准备

统一目录：`../datasets/mpc-flatland-v1`。包含三个已有七车场景副本，九份无/低/高扰动事件表，以及SHA256清单。原配置此前已观察，因此明确是开发数据，不冒称新保留集。prepare重复运行会核验场景与事件一致。

每40步选两车发STOP命令3步为低扰动，每20步两车8步为高扰动；事件按时钟固定，不依赖方法轨迹。STOP是动作级扰动，不保证高速运动中立即物理静止；轨迹应核查实际响应，不能称为严格冻结。运行器关闭原生故障生成器，避免与外部事件混淆。

## 初始安排与五种对照

所有方法共用固定单路线，按列车编号给顺序出发时刻。fixed还要求前车完成才放行下车，是保守工程参照，不是同机制消融。初始安排尚需无扰动完整运行确认，不能凭构造宣布已验证可行。

- fixed：固定路线与顺序放行，不在线协商。
- periodic：每8步提出修订，缺计划时补提案。
- single：条件触发，单项响应。
- menus：同样触发，最多3项响应，单轮。
- feedback：最多3轮，后续扩大响应覆盖。总检查预算比单轮多，不能称等预算消融。

当前基础适配器在8步到期时也触发更新，因此事件触发并非完全区别于周期更新。进入正式比较前需区分“内部检查/续期”和“对外协商”，否则不能据结果声称事件触发通信优势。组合检查与运行上限均受限；每次运行保存核心和脚本快照，结果是新版本，不复用旧成绩。
