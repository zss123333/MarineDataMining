# 同构Agent核心

当前冲突处理口径：找不到组合只是旧事务结束，不是任务失败。适配器应反馈具体约束和等待/保持/局部修复响应，核心在硬约束可行的菜单中选择总代价最低项。单轮预算耗尽后记录pending_revision，保持有效旧安排或调用安全动作，在后续观察轮继续。prepare失效也保留后续修订请求。abort仍用于撤销旧事务、释放准备锁，不能删掉这一安全机制；它不等于整个系统中止。没有可行方案时不能强行提交冲突安排，更不能保证任意不可行任务都能成功。

首次阅读请先看[快速阅读指南](快速阅读指南.md)，再按start→think→act的顺序读agent.py。关键对象和提交分支已加中文说明。

更新：2026-11-13。`agent.py`负责任务无关的决策、消息、协商和执行屏障；任务代码留在适配器中。所有成员使用同一个Agent类，成员目录至少包含三个不同身份。

## 已提供的通用能力

- 本地响应和私有计划：仅公开条件、成本及选项编号参与组合；各方自行安装自己的计划。
- `Ledger`维护`Commitment`和`Dependency`：版本替换、未来使用窗、释放、过期和撤销；依赖窗口必须落在承诺有效期内。
- 内部修改直通：适配器同时实现`local_revision`和`external_conditions_unchanged`，核心检查可行性和版本后本地安装，不发协议消息。不能确认无外部影响时继续正常协商。
- 参与者选择与依赖扩展：`proposal_participants`选初始范围，登记的依赖及`coordination_peers`补齐成员；有跨组成员时中止旧提案并重新收集响应。
- 局部修复选项：`repair_options`返回修复响应，与保持和调整选项一起比较；私有修复计划仍保留本地。
- 有限多轮重新求解：`negotiation_constraints`从不兼容响应生成新约束，放入新Proposal.constraints，所有成员重新生成响应。默认最多三轮；缺省没有该回调时只做一轮菜单组合。
- 反馈边界：`feedback_boundary`返回绝对轮次，核心在边界处停止旧方案，要求重新规划；`execution_valid`检查任务侧期限及条件，不可继续时调用`safe_action`。
- 撤销：start和act发现不可行都走同一通知路径，优先通知登记依赖及任务报告的相关成员。旧适配器没有依赖信息时保守通知任务组，不能冒称精确通信。
- 评估复用：`evaluation_key`声明评估所依赖的状态指纹，核心结合候选、参与者和约束缓存，命中仍调用valid，安装或撤销会清空缓存，最多256项。适配器不提供可靠指纹时不缓存。
- 差量响应：构造时设`delta_messages=True`，首份发完整版本，后续仅在编码更小时发差量；接收端核对基版本并还原，缺失基版本中止本轮。默认关闭以兼容旧日志。

## 适配器契约

### 局部补丁与连锁影响

任务可以用`SegmentedPlan`保存多个私有片段，用`PlanPatch(base_versions, updates)`作为Response.private_plan。base_versions是本次响应依赖的读取版本，updates是写集合；apply只替换写集合，未涉及的任务内容和版本不变。valid应调用分段计划的valid，而不是仅依赖整个Agent的全局版本。补丁写集合必须包含在读取版本集合中，过期相关版本禁止安装。

`response_dependencies(proposal, candidate, response, observation)`在生成每项可行响应后返回该响应将影响的成员。发现未纳入者时，不提交当前响应，而是请求expand；旧提案中止，扩展后每名成员重新响应。成员目录有限且只扩不缩；循环依赖不会无限增加成员。依赖识别仍由适配器负责，当前合并全部可行选项的依赖，宁可多联系而不漏掉。此能力已在独立007任务验证，Flatland仍使用其原路线适配，并未自动变成分段任务系统。

基本任务接口为`Task`；新扩展明确列于`AdaptiveTask`。扩展通过可选回调读取，旧适配器仍可运行，但不会自动拥有缺失的任务能力。

`commitment_records(observation)`返回本地已知的承诺和依赖记录。承诺替换必须递增版本；同一依赖更新也需新版本或新key。任务完成依赖后调用`agent.ledger.release(key)`，不再对外履约时调用`release_commitment(key)`；撤销和过期由核心处理。适配器必须按实际任务维护记录，核心无法凭空推导工具或交付物之间的因果依赖。

`external_conditions_unchanged`必须依据对外条件检查，不得仅检查当前无碰撞。`feedback_boundary`返回大于当前轮次的绝对轮次；任务若使用独立时间轴必须转换。`evaluation_key`必须覆盖状态、时间、版本等会改变响应的因素。`repair_options`应只修改任务定义的受影响部分，核心不会自行生成铁路或工具动作。

协议仍假设同步可靠投递及准备到提交期间状态冻结。`Clock.exchange`必须完成协商后才允许执行。锁拒绝并发准备，不保证无饥饿或异步容错。

## 实现与证据边界

本轮补齐通用扩展能力，不等于Flatland已经启用全部回调，更不等于已证明降本和任务收益。Flatland已加执行期限拦截与安全停止，但精确影响判断、动态反馈边界、任务依赖记录和局部片段修复仍须按铁路语义接入，不能用空实现伪造完成。

方案见[创新方案设计](../创新方案设计.md)，历史缺口及本轮对应关系见[方案实现核查](方案实现核查.md)。所有测试、环境及实验结果见[实验目录](../expr/004-distributed-agent-core/README.md)。旧批次绑定旧源码，不代表本轮新核心结果。
# 大模型决策入口（新增）

`Agent(..., decision_model=OllamaDecisionModel())`启用真实模型决策；客户端在`llm.py`。核心在发起变更时调用模型形成候选，在收到提案时调用模型形成自己的响应，组合冲突后携带新约束再次响应。任务插件需实现`decision_context`、`candidates_from_decision`和`response_from_decision`，负责定义公开输入及把模型输出转换为可执行局部补丁。

未传`decision_model`时保留旧规则接口，方便回归测试与规则基线；不能将这种运行称为LLM Agent。非法响应会向模型反馈后重试，连续失败会明确报错，不静默换成规则答案。真实验证和提示、合法输出域的定义见`expr/011-llm-coordination`。
