# 从“预测整个 Agent”收敛到“一次工具返回”：不足、缺口与小改进

更新：2026-11-08。依据[文献总览](总览.md)、已完成的三篇核心笔记，以及本轮补查的相关工作。**本文是选题取舍和待验证设计，不是新算法证明，也不是实验结果。**

## 一、先改变目标：不研究通用机制，只改一个使用环节

上一版“低开销剩余token上界预测＋校准＋预算控制”仍然太大：同时涉及预测模型、统计保证、闭环决策、压缩和早停。每项都能独立成题，还容易复刻BAGEN、ContextBudget等已有工作。

本次收敛为：

> **海洋质检 Agent 的“统计卡先看、异常行再取”：能否在不丢证据的前提下，比直接返回整张表更省 token？**

只改一个工具的返回方式，不换模型，不训模型，不改Agent总体架构，不做通用剩余长度预测，不加入停止、模型路由、多智能体或强化学习。

这里的“小创新”定位是**把一种已有的按需取证思路，改造成保留海洋质检口径与可核验证据的工具交互，并以实验找出适用条件**。不是发明按需加载，也不能预先称为领域首创。

### 1.1 保留原来方向里有用的部分，放弃过重部分

| 保留 | 暂时不做 |
| --- | --- |
| 测量Agent使用中的真实token消耗 | 预测完整任务还需多少token |
| 工具层的小改进和A/B实验 | 训练预测器、探索隐状态机制 |
| 记录当前返回内容实际长度 | 为已知内容训练“长度预测器” |
| 用历史成本作可选展示 | 校准上界、概率安全或普遍最优声明 |

工具返回已经生成时，其字符串可以直接计数，没必要预测。真正未知的是Agent后面会展开几次、还要运行几轮，核心实验不尝试解决这个新问题。若课程报告必须出现“预估”，只展示**发送前的token报价**，明确它是已知候选内容的计数/估算，不包装为输出长度预测创新。

## 二、文献覆盖边界：什么已核查，什么只是候选

“所有相关工作”在本文指**当前已识别的相关工作集合**，不是声称穷尽整个领域。证据分三层：

- **A：已读PDF与代码、已有笔记。** BAGEN、TIE、BATS，可支持具体设置与结论讨论。
- **B：本轮/前轮核查arXiv摘要与项目入口。** 可判断研究对象和概括性重叠，不能据摘要断言作者完全没有某个实验或功能。
- **C：工程基线与常见做法。** 用于避免“重新发明分页/字段筛选”，不是某篇论文的实测结论。

下文的“未回答”通常表示**现有已核查证据不能回答本课题的问题**，不等于作者有缺陷。原本服务于推理调度的工作没有海洋实验，不应被当成不合理设计。

### 3.4 工程做法：比论文更容易忽略的“已有人会做”

分页、`LIMIT`、字段投影、服务端聚合、按ID取详情、外部存原文、缓存重复查询，以及只读工具与副作用工具分离，都是成熟工程方法。我们的设计大部分由这些积木组成。

如果实验只证明“1000行全量比10行摘要更贵”，贡献很弱。真正需要证明的是：**与分页、短摘要等同样简单的方案相比，加入少量必要口径和定向证据入口，能否用很小的额外开销减少误判与回取。**

## 四、共性不足与缺口：分清证据、需求和新颖性

| 问题 | 目前能确定的事实 | 可做的具体改进 | 结论强度 |
| --- | --- | --- | --- |
| “少token”与任务正确脱节 | 已有研究明确指出质量/时间/费用不可互代 | 将末态判定、净token和回取同时报告 | 评测原则，非创新 |
| 无数据被当成无异常 | 课程已有对应失败案例；本地任务可直接构造 | 卡片强制带查询状态、样本数和覆盖 | 课程场景的工程改进，非首次结构化返回 |
| 摘要省掉单位、分母和版本 | 是本场景的合理风险，尚未完成实测 | 字段白名单保护，比较普通短摘要 | 待验证假设，不能先说现有论文均失败 |
| 回取太多抵消压缩收益 | DTOC和成本归因已有相关讨论 | 以异常ID定向展开，测回取次数和净成本 | 增量应用与适用区间，非首次回取机制 |
| 简单基线没被公平比较 | 已识别工作设置不同，不能凭摘要断言它们全部遗漏 | 强制与分页、普通紧凑表比较 | 本项目设计要求，不冒充文献公认空白 |
| 单模型结论不稳 | 相关摘要已报告模型依赖或harness依赖 | 先固定1个模型完成，预算允许再用第2个验证 | 适用边界，不做普适宣称 |

因此，当前能够负责任地主张的缺口是：**针对我们的海洋质检工具，还没有本地证据说明哪一种简单返回方式，在保持可核验结论时最划算。** 这是明确的课程实践缺口，不等价于全球研究空白。

## 五、缩小后的“新玩法”：质检取证卡

### 5.1 只改变一个接口

假设Agent要回答：“上周某海区质量异常主要集中在哪些站点，依据是什么？”工具已经按固定快照计算好表格。

默认不返回整张站点/观测明细，而是返回固定结构的“取证卡”：

```text
状态：OK / NO_COVERAGE / ERROR
口径：时间窗、单位、质量规则与快照版本
规模：有效样本数、有效站点数、覆盖情况
全局统计：异常总数、异常率与明确分母
异常入口：按确定规则列出的站点ID、计数、证据行ID
省略声明：还有多少行、当前只展示哪些范围
取证入口：按行ID取回原始记录
```

统计由确定性代码生成，不额外调用LLM摘要。按ID取证受固定快照约束，不能先卡片统计v1、后取证读v2。若某错误字段实际拿不到，返回未知而不是补造。

**真正想改进的是“短而有口径、少而可取证”，不是“短就行”。**

### 5.2 一次实际交互的样子（虚构示例）

1. Agent查询上周区域质检。
2. 工具先返回卡片：“有效1000条，异常40条；其中站点A有30条；其余明细未加载；快照S1。”
3. 问题只需主要异常站，Agent据卡片可给出带分母结论；需要证据时，仅取A站的指定异常行。
4. 若覆盖为零，工具明确返回NO_COVERAGE，正确结论是“无法判断”，不是“质量良好”。

示例中的1000/40/30仅说明交互，不是实验结果。异常入口的top-k会有遗漏风险，不能把局部清单当全部异常；问题要求完整列表时必须分页或取全。

### 5.3 三个明确不做

- 不判断整个任务会花多少token，也不对任务作不可完成预测。
- 不自动终止Agent或更改模型，只由原有流程正常完成。
- 不压缩所有历史，不引入学习型压缩策略；可控变量只在该工具输出。

## 六、最小实验：先做一张表，不做一个框架

### 6.1 一个任务族、一个工具、一个模型

只选“区域站点质检归因＋证据引用”任务。模型固定，温度、最大输出、步数上限与系统提示固定。原始表和快照固定，模型只读，不接真实海洋写入或告警。

优先用许可明确的真实样例；若用合成表，明确是工程验证，不能声称发现海洋规律。每题有代码可判定的异常站、计数、分母和正确证据行；歧义题事先排除或定义并列。

### 6.2 四组足够，不再加复杂模块

| 组别 | 返回形式 | 要回答的问题 |
| --- | --- | --- |
| A 全量 | 同一份完整表 | 浪费上限参照，不是唯一竞争对手 |
| B 分页 | 固定页大小，按需下一页 | 普通工程做法是否已经足够 |
| C 普通紧凑卡 | 相同基本聚合和取证能力，但省略口径保护字段 | 缩短本身能做多少，是否引入误判 |
| D 口径保护卡 | C基础上加状态、覆盖、分母、版本与省略声明 | 保护字段是否值得付出额外token |

所有组底层是同一数据，能力不被暗中剥夺；提供相同定义的按ID证据能力和正常错误返回。B的分页范围/排序固定，C/D除预先规定的字段差异外一致。C不是故意捏造错误摘要，而是常见的简洁返回；D也不得直接塞入最终答案而不给其他组等价查询能力。

### 6.3 数据量与病例先预注册

建议先20题试跑查接口，再冻结为60题，每题3次、四组共720条运行；这是建议规模，不是已完成数据。60题可均分：普通定位、长表稀疏异常、异常分散、无覆盖、单位/分母敏感、必须展开才能核查的证据题，各10题。种子和表规模分布提前固定。

所有变体基于同一题配对比较，不按挑中的成功轨迹汇报。开发题与最终测试题分离；最终测试不再调top-k、字段和分页长度。预算不足时缩题量并报告不确定性，不通过只留好看题目省钱。

### 6.4 成功必须可检查

成功要求同时满足：站点/异常判断正确、计数与分母正确、单位和时间正确、引用行存在并支持结论；无覆盖时不宣称良好。按任务预定义哪些字段必答，避免用统一长答案模板迫使所有组无谓输出。

“有证据”不能只检查引用ID格式，还要核对行内容。额外标记状态混淆、遗漏、错误分母和不支持引用。自动规则无法判定的解释段由盲审处理，不直接用同一模型自评成功。

### 6.5 只看五项主读数

1. 全测试任务成功率及配对置信区间。
2. 每任务总输入、输出token；失败也纳入均值，不能只统计成功样例。
3. 净费用：区分缓存输入、未缓存输入、输出，按实际提供的usage统计。
4. 取证回取次数、增加轮数和端到端耗时。
5. 状态/分母/证据错误率，验证D是否确实比C更可靠。

`净token节省率 = 1 - D组全部实际输入输出token / 参照组全部实际输入输出token`。至少分别对A/B/C报告，不只挑最好比较。工具输出占用是原因指标，总API输入输出才是最终指标；隐藏推理若不可观测要说明。

若恢复、提示字段、历史重传使D更贵，必须如实计入。缓存可能让token少但费用不降，因此费用和token分别报告。

### 6.6 哪些结果会否定这个小改进

- D只胜过全量A，却不优于分页B：结论降为“分页已足够”，不硬说创新成功。
- D比C更正确但更贵：呈现质量—成本权衡，而非宣称双赢。
- D频繁回取导致总量/延迟增加：说明卡片过小或任务不适合。
- 原有Agent本来就只读必要行：没有真实浪费，停止本题，不人为改坏基线。
- 同样证据要求下成功率下降：不得把少回答或漏取证造成的减少当节省。

## 七、最终可写进作业的原创性表述

可用：

> 我们没有提出通用长度预测算法，而是在一个固定海洋质检任务中设计口径保护的统计卡，允许Agent按证据行定向展开。通过与全量、分页和普通紧凑卡配对比较，研究少量语义保护字段能否减少错误与回取，并获得可核验的净token收益。

不可用：首次按需加载、首次可逆压缩、首次预算感知、首次发现历史重传昂贵、首次保证无损节省，或“现有工作都只压缩不管质量”。这些不是已获得证据支持的声明。

该表述有改进思路、有使用玩法、有可否定实验，也对应课程“空结果不等于良好”“工具返回附口径”“按真实成本验收”的知识点。贡献大小由结果决定，不因给方案起新名字就成立。

## 八、当前决策与下一步
