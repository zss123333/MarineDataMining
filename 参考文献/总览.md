## 1. 把方向缩小：预测什么，节省什么

建议题目：**面向工具型 Agent 的低开销剩余 Token 上界预测与风险约束预算控制**。

先区分四个对象：单次调用输出长度、下一轮增量消耗、整条剩余轨迹消耗、任务完成所需最小成本。前两者不等于后两者，观察到的一条后续轨迹成本也不等于理论最小完成成本。

输入上下文已有内容可直接用匹配 tokenizer 计数，不必用预测模型估计；真正未知的是未来输出、工具返回与未来轮数。还要区分：生成 token、重复提交的输入 token、缓存 token、隐藏推理 token 和费用。主实验同时报告输入/输出 token 与实际可观测总成本；不能只减少输出却让历史重放成本增加。

## 3. 已有工作决定创新边界

| 工作 | 已经做到 | 不能直接推出 |
| --- | --- | --- |
| TIE | 对随机输出预测分布，用尾风险排序请求 | 调度加速不是少生成 token；不是完整 Agent 剩余成本 |
| BATS | 展示已用/剩余工具预算，调整搜索与验证 | 剩余额度已知不等于未来需求可预测；统一费用下降不等于同比 token 下降 |
| BAGEN | 每个轨迹前缀估计剩余区间/IMPOSSIBLE，早停与 SFT/RL | 不能再把“预测剩余 token＋早停”作为全新概念 |

BAGEN 报告失败轨迹 token 节省 28—64%，不能写成全体任务平均节省；还存在误终止与成功率损失。其最高 47% 覆盖描述针对训练后相关设置，不能忽略其他环境表中的不同覆盖率。TIE 报告的 2.31×/1.42×是延迟/吞吐指标，不能转写成 token 节约率。

## 4. 可探索的具体差异：尚未证实新颖性

提出一个待检验组合，而非预先命名“新算法”：用廉价可观察轨迹特征拟合剩余成本分位数，按任务独立的校准集构造上界；将上界与失败风险结合，在继续、压缩工具输出、切换确定性流程和停止/转人工之间做受限选择。

特征候选：已用输入/输出、轮数、最近几轮增量、工具类型、返回长度、错误和重复调用、可核验子目标进度。禁止使用未来成功标签、最终轮数或后续工具结果作为输入。商业 API 不保证能拿到隐藏状态，主方案不依赖隐藏状态；不得把隐藏推理文本作为必需特征。

与 BAGEN 的待检验差异是**无需每步额外大模型自估、显式校准、净节省记账与同成功率约束**，不是首次预测区间。与 TIE 的区别是轨迹级和策略反馈，与 BATS 的区别是预测需求而不仅展示余额。仍需补查校准早停、预算约束 Agent、动态上下文压缩相关论文，才能最终确认贡献。

## 5. 最小可执行实验方案（本人的待验证设计，不是论文原设置）

1. 优先使用 BAGEN 公开 Search-R1/Sokoban 轨迹验证预测，避免先付费生成大规模日志；先核验许可、清单和实际条数。
2. 按任务身份分 train/calibration/test，不按前缀随机拆分；同任务所有轨迹和前缀同组。预算档位也不能利用测试后缀分布调参。
3. 目标分别记录：未来可观测输出 token、未来输入重放 token、总计费 token；截断、失败和自然完成分开，不将失败余量误当成功完成成本。
4. 基线：固定上限、历史均值/分位数、最近成本线性外推、预算提示、Agent 自估区间；新方案先用简单分位数回归，再消融校准、错误特征和进度特征。
5. 首阶段只做离线预测：MAE、分位数损失、覆盖率、区间宽度、低估率、按任务等权结果；校准不能仅靠无限放宽区间。
6. 次阶段在可控环境在线运行：固定种子、模型、工具快照/缓存、温度、最大输出与重试。至少3个独立种子，配对比较并按任务 bootstrap 区间。
7. 在线对比先只改变停机；压缩/路由作为后续独立变量。压缩会改变后续轨迹，不能用原后缀冒充压缩后的反事实结果。
8. 同时报告成功率、错误终止率、总/输入/输出 token、预测器自身开销、恢复/重试成本、延迟和每成功任务成本；画成功率—净成本 Pareto 曲线。

净节省率 = `1 - (受控执行 + 预测 + 摘要/路由 + 恢复的总计量成本) / 基线总计量成本`。费用和 token 两套统计分开。预先约定允许的成功率下降阈值，再选择政策，不能在测试集挑最好看阈值。

校准警告：split conformal 等覆盖保证依赖交换性，按前缀看似覆盖良好不代表每条轨迹任意时刻联合覆盖；在线策略改变分布后也不能直接沿用静态保证。课程作业可先报告经验覆盖，不宣称无条件理论安全。

## 6. 与海洋数据挖掘的结合

可构造小型海洋质检工具环境：区域编码、站点统计、查询质量规则、核对异常、输出带来源结论。注入无覆盖、参数错误、超时、长工具输出和重复查询。任务成功由明确末态断言判定，不由模型宣称完成。先用公开 Agent 基准验证，再把海洋任务作为迁移测试，不将自建少量题目宣传为通用 benchmark。
