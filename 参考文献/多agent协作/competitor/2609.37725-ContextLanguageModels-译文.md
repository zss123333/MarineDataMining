# Context Language Models：摘要及核心内容中文译文

[返回论文笔记](2609.37725-ContextLanguageModels.md)。依据arXiv:2609.37725v1。以下完整翻译摘要，选译核心方法、数据和实验，不是27页逐字翻译。分析与批评放在笔记，不作为作者观点。

## 一、摘要（完整翻译）

我们提出上下文语言模型（Context Language Models，CLM），即能够原生管理自身上下文的语言模型。实现方式是把上下文视为文件，允许模型不受预定义操作形式限制地更新这个文件。这样，模型可以学习哪些信息最值得保留，也能自然扩展到多个Agent上下文以文件形式共存的多Agent系统。

利用已有模型零样本构建的CLM，在多种任务中优于当前领先的上下文管理策略：BrowseComp-Plus准确率提高11.4%，同时FLOPs减少21.5%；12小时EdgeBench得分提高5%，FLOPs减少59%；24小时多仓库Agent群体任务中，以相同计算量取得大65%的改善幅度。

此外，将上下文管理从外部harness控制转为模型内在行为，使CLM能够通过上下文学习和参数学习改进管理策略。我们说明，通过标准技能优化循环演化自然语言指令，可以在降低计算量的同时，让一个上下文管理任务的保留集准确率最多提高35.9个百分点。我们还提出CLM在线强化学习方法，使Qwen3.5-9B在BrowseComp-Plus上的表现提高47.6%，同时FLOPs减少12%。最后，我们共同设计了用于CLM服务的后缀缓存复用（Suffix Cache Reuse），在相同性能下，相比标准SGLang进一步减少35%的服务端计算。

## 二、问题设定和诊断任务

现有语言模型通常只将新输出追加到上下文。CLM则把上下文转换交由模型控制：模型不只是产生要追加的内容，也决定下一轮上下文本身。

ContextBench通过四个合成任务隔离管理能力：Needle Retention检查选择性逐字保留；Sudoku Sketchpad检查对当前状态进行局部修改；KV Store和Log Triage检查将大量信息卸载到文件后准确检索。输入按连续操作送入同一对话，操作在Agent行动前进入上下文。

上下文限制32768 tokens，其中2048用于响应。生成器限制单次操作大小及必需保留内容，使任务在预算内可解。上下文压力定义为整局输入总量与上下文限制之比，最高约24倍。

## 三、把上下文实现为文件

我们将当前上下文映射到可直接编辑的文件，在系统提示中提供路径。模型可以通过通用Bash命令编辑它，就像编辑其他文件。不同之处在于，这个文件的修改会自动同步到模型上下文，再送到服务端继续生成。不编辑时，生成内容仍按默认方式追加。

多个上下文文件可以分别与模型服务保持同步。通过创建和删除额外上下文文件，可以初始化和终止子Agent。模型还可以维护进展表、压缩旧搜索结果，或者定义可复用的整理函数。

## 四、在上下文中学习与强化学习

自然语言指令或技能文档可以直接指导上下文管理。技能演化时，提出者根据训练轨迹生成候选技能，在开发集上选择；演化结束后，最终技能只在保留测试集上评估一次。提出者可以是更强外部模型，也可以是Agent自身。

强化学习使用逐步GRPO：先采样完整Agent轨迹，按最终任务奖励计算组相对优势，再将该轨迹优势赋给各调用片段。

仅用任务结果难以区分高效与低效编辑；直接奖励编辑次数或删除量又可能诱发无用编辑和信息丢失。因此我们增加成功门控的效率优势，只在成功轨迹之间比较推理FLOPs。比成功组平均成本低的轨迹获得正效率优势，比平均高的获得负优势。失败轨迹以及成功少于两条的组不获得效率信号。最终结合任务优势与效率优势，鼓励正确且高效的执行。

## 五、后缀缓存复用

如果上下文中的B被B′替换，标准前缀缓存只能保留第一个不匹配位置之前的状态，后面的未改文本也要重新计算。SCR复用所有保留token的旧缓存，只为新增或插入token重新prefill。

保留后缀的缓存仍编码旧前缀，属于过时状态；有时它还能保留过去更丰富的信息。正文主要成本仍按标准前缀缓存估计，SCR的额外节省单独报告。

## 六、数据和实验设置

终端代码评测使用TerminalBench2.1的89个任务，以及TBLite；深度研究使用BrowseComp-Plus全部830题。主零样本模型Qwen3.6-27B，并补充Qwen3.5-9B。所有方法使用共同的基础Agent框架，比较最终任务正确性与前缀缓存下的计算量。

开放发现任务包括4个数学优化问题；EdgeBench10个任务，每个3种子、最长12小时；以及6个仓库的多Agent优化，超过24小时，并用17个未向Agent公开的下游CPU基准评测。

强化学习使用OpenResearcher3040训练题、500验证题，在验证集选择checkpoint，再评估BrowseComp-Plus830题。每步8题、每题32条轨迹，训练70步；学习率10^-6、效率权重0.25。训练policy使用16块H200，轨迹生成使用48块H200。

## 七、主要结论

BrowseComp-Plus零样本准确率59.4%，比最强Summary基线相对提高11.4%，计算量低21.5%。TBLite为73.7%对67.0%，使用91%的FLOPs；TerminalBench达到相近质量并减少计算。

RL后CLM从28.8%升至42.5%，提高13.7个百分点，即相对47.6%；计算量从1.52降至1.34PFLOPs每题。训练后的Summary为42.1%、2.19PFLOPs每题。

SCR评测中，两种服务准确率均60.2%，计算量由10.98降至7.14PFLOPs每题，约省35%。这说明在所测设置下，后缀缓存复用可以降低重复prefill开销。

## 八、讨论

允许模型编辑上下文也产生安全问题：模型可能删掉重要限制，或隐藏不当行为。上下文自由管理需要与外部安全措施结合。编辑也会损害前缀复用，因此服务优化与模型策略需要共同考虑。
