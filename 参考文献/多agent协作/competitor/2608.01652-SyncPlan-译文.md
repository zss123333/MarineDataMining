# SyncPlan：显式同步和自适应纠错的长程 LLM 协调——核心中文节译

[返回笔记](2608.01652-SyncPlan.md) · [原文全文](https://ar5iv.labs.arxiv.org/html/2608.01652)。摘要、方法及实验核心内容节译；不宣称全文逐句翻译。

## 摘要

基于 LLM 的多智能体协调在动态环境中面临效率与适应性的基本权衡。现有方法通常依赖重复调用 LLM 或多轮通信来调整执行决策，带来较高延迟，并容易受到异步进度和环境变化影响。相反，一次性规划减少协调开销，但开环计划可能很快过时，尤其当动作依赖其他智能体和环境时。

我们提出 SyncPlan，通过显式同步和自适应纠错形成规划—执行—纠错框架。给定状态与团队任务，中央 LLM 协调器在一次规划调用中生成各智能体行动链。执行时，显式等待原语和死锁检测强制落实智能体间及智能体与环境间的依赖；轻量计划过时检测器持续判断剩余计划是否因环境变化而失效，并按需触发重规划。我们进一步使用监督微调和规划导向强化学习优化协调器，并采用密集任务进展和结果级反馈。作者报告在 Overcooked 与 Honor of Kings 上获得较高任务成功率，同时显著降低运行时间；摘要称特定对比下运行时间低于现有 LLM 协调器的 0.05%。代码与数据将公开。

## 方法：协作规划与运行时同步

协调器接收任务和环境状态，输出每个受控智能体的行动链。跨智能体依赖由 Wait_agents 表达，环境条件依赖由 Wait_entity 表达。执行模块维护各链当前指针：普通动作完成后推进；等待条件不满足则输出空操作，其他智能体可以继续执行。

等待关系组成有向图。当图中出现循环等待，系统检测到死锁并触发重新规划。无死锁并不足以说明计划仍合理，因此还需要检查环境变化是否使剩余计划失去依据。

## 方法：计划过时检测与训练

PSD 输入剩余行动链与实体的关联、实体当前状态、实体状态变化。相关性张量把注意范围限制到剩余链涉及的实体。轻量网络输出重规划概率，超过选定阈值后调用协调器。

Overcooked 的检测正例来自会使行动链失效的注入事件帧，负例来自无注入轨迹，按 1:5 采样。HoK 检测正例离线合成并人工审核。两环境训练数据分别构造，训练与验证为 8:2，验证集选择阈值 0.7。协调器另行通过 SFT 学习行动链，再用规划导向 RL 改善任务表现。

## 实验与主要结果

Overcooked 使用三种布局，并构造持物掉落、锅内材料散落和智能体位移事件。带种子脚本让各方法看到相同扰动。HoK 不在评估阶段注入脚本事件，扰动来自其他英雄的自主行动。

动态 Ring 设置中 SyncPlan 达到 88.3% 任务达成率，超过所比较 LLM 基线，但未超过最强 RL 基线。HoK 中达到 86.3%，高于比较基线的 68.75%。消融表明，PSD 对动态条件尤其有用，而标准条件中可能没有额外成功率收益。训练、同步和自适应纠错共同构成方法，不能将完整模型结果理解为纯提示方案的结果。
