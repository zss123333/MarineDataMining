# 从Stronger-MAS借鉴什么实验方法

2026-11-12。[论文笔记](competitor/2510.11062-StrongerMAS.md) · [核心译文](competitor/2510.11062-StrongerMAS-译文.md)。本文件是我们的迁移分析，不是作者原有实验，也不是已执行结果。具体待执行方案统一放在[实验设计](../../expr/004-distributed-agent-core/MPC降本与协作归因实验设计.md)。

## 一、最值得学的不是训练规模，而是拆分解释

只比较“完整方案”和“独立Agent”，无法知道提升来自更多候选、更多轮数、工具帮助，还是成员真正配合得更好。Stronger-MAS把提示式协作、训练、共享模型、专用模型和多轮交互分开，比单个最高成绩更有参考价值。

我们当前保留集完整15/28、单响应15/28，意味着“多给配合选项”在这批实例上没有带来额外完成收益。应分析什么情况下选项有用，而不是直接上训练或扩大场景数。

## 二、逐项迁移

| 原论文实验 | 它回答什么 | 我们可以怎样做 | 不能据此声称什么 |
| --- | --- | --- | --- |
| SA、提示MAS、SA+RL、MAS+RL | 角色分工与训练分别有多少贡献 | 固定规划器，分开比较独立、只确认、单响应、多响应、降本版 | 更多模型调用本身就是协作创新 |
| 多轮SA | 改善是否只是多想几次 | 给独立方法相同候选评估和计算预算，不只每轮次数相同 | 同上限就等于实际计算相同 |
| 同节点K分支 | 比较输入是否真的相同 | 保存同一环境快照与各成员私有状态，分支回放不同协调方式 | 只贴开关标签就是端到端消融 |
| 独立训练后拼接 | 单项能力改善能否替代联合适应 | 固定各方候选，比较独立最优拼接与条件协调 | 无训练实验可称复现AT-GRPO训练结论 |
| 交换角色策略 | 策略是否学到了不同职责 | 将不同队友的响应风格交叉配对，检查是否过拟合固定队友 | 同构核心成员换ID就等于角色策略交换 |
| 共享与专用策略 | 专门化是否值得额外模型成本 | 如后续训练，先共享基座，再考察角色适配；当前优先共用小模型 | 多个Agent必须部署多个模型 |
| 稀疏奖励消融 | 结果是否主要来自奖励提示 | 移除修复代理和额外启发，保留相同安全约束与任务指标 | 删除安全校验就是公平消融 |
| Agent数量扩展 | 人数增加时收益是否保持 | 固定地图配置族，测3、5、7等人数，分别报告总预算和每人预算 | 人数与总计算一起增加还叫固定预算扩展 |
| 平均对齐轮数曲线 | 更好协作是否减少反复交互 | 记录每个确认窗口的消息轮数、修改次数、失败重试和完成时间 | 双方同意就等于执行正确 |
| 延迟分解 | 单步更贵能否靠整局更短抵消 | 分开记规划、通信、组合搜索、模型推理、环境推进 | 失败早停也算效率提升 |
| 两个模型规模 | 方法是否只适合一种能力水平 | 先Qwen2.5-1.5B；可选更大模型只作敏感性，不改变主目标 | 作者Qwen3-1.7B结果直接适用于我们的Qwen2.5 |
| 成功失败对话案例 | 数字背后发生了什么 | 展示未来依赖、请求、配合选项、确认、实际动作及恢复 | 挑一个成功案例代替总体比较 |

## 三、特别重要：同状态分支，而不是强求全过程输入一样

框架一旦改变动作，后面轨迹和输入自然会不同。端到端效果比较应固定初始条件、可获得的信息类型、模型、工具与预算规则，而不是要求所有后续消息逐字相同。

要研究“这一刻协调有什么用”，则需要在同一个完整快照处分支：恢复相同环境随机状态、位置、故障状态，以及每个Agent自己的计划、版本、承诺、缓存和模型历史。分支后分别运行协调与不协调，并记录后续结果。这与论文在同一提示节点采候选的原则相近，但不是同一种训练算法。

我们此前的qwen-matched-probe只对相同输入重复调用模型，开关标签没有真正改变协调，不能回答这个问题。动作重放也只确认环境位置，未恢复私有计划，不是完整快照分支。

## 四、如何看“效率改善”

至少同时报告三类数据：

1. 任务结果：到达比例、严重失败、惩罚完成时间。
2. 协调工作量：有多少次真的重新协商，每次多少参与者、候选、响应和组合检查。
3. 计算与通信：真实消息字节、LLM输入输出token、工具调用、在线墙钟。

论文中Game变快的原因是更早成功，而Code变慢。因此我们也不应预设“多Agent协调一定省时”。应画出不同预算下的质量—成本曲线，检查是否存在同等完成质量下成本更低的配置。

## 五、不要照搬的部分

- 8×H100与150步RL不是我们课程作业的前置条件。
- 最短路oracle、golden tests等用于奖励检查时，不能把隐藏正确答案给在线决策者。
- 其双角色工具系统不等于我们三个及以上执行者的资源协调。
- 贪心验证分数不一定保留长期价值排序，不能据此证明“最近一步省时就最好”。
- 原文部分表格、复杂度表述有不一致，迁移时复核而不照抄。
