# MPC–Agent：新颖性初筛与速度优先投稿决策

检索日期：2026-11-08。目标：尽快形成可投稿论文，并尽快获得正规期刊录用通知。本文件是摘要级选题排查和期刊证据核查，不是逐篇精读笔记，不替代后续按指定 README 完成的 Zotero 归档、原文阅读、译文及图表笔记。

## 1. 结论先行

1. “记录队友依赖—检查计划变更—局部修复”这一通用方案，新颖性不足，不能直接作为已经通过验证的创新点。上一轮将它推荐为可快速成文的方法，低估了已有计划修复和依赖图研究的重合。
2. “承诺是多 Agent 协调变量”“滚动规划时保留外部一致性”“失效后仅修复必要部分”均已有近邻工作。警告带图形化、增加元认知命名本身不能解决重合。
3. 值得低成本验证的候选：异步多 Agent 中，基于显式依赖确认的选择性承诺修订。只冻结已被队友实际采用的承诺，允许其他部分滚动更新；修订时处理版本、受影响依赖和修复范围。该组合仍未通过全面新颖性核查，不能宣称首次提出。
4. 速度优先的条件性主投：IEEE Access。前提是单位认可、接受 APC、完成技术有效性与实验证据。它不是高录用率期刊：官方当前页面给出的典型录用率约为 20%。该总体统计不能换算成本文录用概率。
5. Applied Intelligence 暂列备选；JAAMAS 不作为速度优先主投；ESWA/EAAI 的官方周期本轮未成功获取，不能据此把它们排在速度优先主投位置。

## 3. 近邻工作与重合边界

| 工作与核实状态 | 已有内容 | 对本选题的影响 |
| --- | --- | --- |

| [Self-triggered min-max DMPC for asynchronous multi-agent systems with communication delays](https://arxiv.org/abs/2106.05358)，2021，核实到预印本 | 自触发执行与轨迹广播；限制新预测轨迹偏离旧广播轨迹的一致性约束；可行性与稳定性分析 | “内部更新但对外保持可靠”不是可直接独占的创新 |
| [SyncPlan](https://arxiv.org/abs/2608.01652)，2026，核实到预印本 | 中央 LLM 一次生成分 Agent 行动链；wait 与死锁检测维护依赖；轻量计划过时检测触发重规划；还包含训练 | “少调用 + 显式依赖 + 触发纠错”已有人做；不能仅以不训练当作充分创新 |
| [Falsifiable Commitment Planning for Self-Correcting Web Agents](https://arxiv.org/abs/2607.24167)，2026，核实到预印本 | 承诺单元携带确认/证伪证据与置信度；执行前后测试；按失效层级局部修复 | “可检验承诺 + 元认知检查 + 最小修复”在单 Agent 已有近邻；多 Agent 化也不自动构成充分贡献 |
| [Replan, Repair, or Edit?](https://arxiv.org/abs/2609.19654)，2026，核实到预印本 | 比较旅行任务中的全量重规划、层次修复与局部修订，并评估已接受安排的保留和计算成本 | “少改原计划、少 token”已有成熟比较视角；任务不同，不等于直接解决团队依赖 |

## 4. 候选设计：只保护已经产生依赖的承诺

临时题目：**面向异步多智能体的依赖确认式选择性承诺修订**。不预设元认知为标题关键词，不预设必须使用 LLM。

区别于冻结整条广播轨迹或统一承诺期限：允许 Agent 自由更新未被使用的承诺；当队友确实基于某承诺安排任务后，记录一条带版本的依赖确认。此后计划变更先检查这些依赖，必要时发出修订通知，由受影响部分执行修复。

最小状态包括：承诺 ID、版本、有效条件、有效期、依赖方及依赖动作。需要明确确认的时机、过期清理、重复消息处理、延迟期间的行为。涉及安全时必须允许紧急失效并及时传播，不能把履约放在安全之前。

预期检验：在异步进度和外部扰动下，是否能同时避免“完全自由改计划造成级联失效”和“全部冻结造成适应迟缓”。这只是待检验假设。版本确认本身属于成熟分布式设计，不是单独创新；还需检索社会承诺、SharedPlans/Joint Intentions、部分全局规划、协作计划修复、分布式事务及版本一致性协议等近邻。

### 必需比较与止损

- 全量重规划、事件触发重规划。
- 简单承诺期限/资源预约，以及静态依赖图保护。
- 无依赖确认、仅版本通知的局部修复。
- 完整方法；去掉依赖选择和版本处理的消融。

匹配环境信息、规划器、计算预算和消息可用条件；把额外通信算入成本。至少测成功率/任务收益、完成时间、无效重规划、依赖失效、通信字节与计算开销。使用 LLM 才额外报告 token。

先复用一个成熟环境，并扩展多个任务实例、随机种子及延迟/扰动强度，不先新建平台。若简单期限或静态依赖图达到相同效果，或收益完全来自增加通信，则停止把完整方案当作独立创新；不能通过删除强基线挽救结论。

## 5. 期刊周期证据

### IEEE Access：条件性主投

- [官方主页](https://ieeeaccess.ieee.org/)明确称 submission-to-publication 为 4–6 周；[评审流程](https://ieeeaccess.ieee.org/authors/stages-of-peer-review/)使用 strives to maintain，属于期刊目标表述，不是每篇保证，也不是本轮抽样算出的录用中位数。
- 官方评审流程给出典型录用率约 20%；至少两份独立评审，采用 accept/reject 二元决策。
- 需要更新的稿件可能先 reject 后允许重投；官方说明只允许一次重投。因此不能把第一轮收到决定视为录用，重投时间也可能超出 4–6 周。
- 范围包含原创技术研发，适合方法与应用实验，不必强行增加学习或控制理论。但仍须证明原创性和技术可靠性。
- 官方主页确认金色开放获取并收取 APC；本轮费用页返回 403，未核实金额，不填未经核实的费用。
- 结论：现有候选中，快速流程证据较明确；没有证据表明它具有最高录用概率，也未证实其为所有期刊中最快。

## 6. 当前投递决定与未决条件

**暂定主投 IEEE Access；Applied Intelligence 列为备选，不是确定的速度第二名。** 不一稿多投，实际切换前复核拒稿原因与备选范围。

该决定有三个前提：单位认可、APC 可接受、新颖性与最小实验通过。现在还不能宣称题目已经具备投稿条件；也没有足够信息给出最高录用概率的排序。

执行顺序：补查承诺/协作计划近邻 → 核实可复用环境与代码 → 用强简单基线做最小实验 → 有稳定净收益才展开完整实验与写作。为追求快速，不投入不必要的训练、机器人硬件和复杂证明；为避免快速拒稿，不跳过近邻对比、通信公平性和消融。

IEEE Access 的[投稿指南](https://ieeeaccess.ieee.org/authors/submission-guidelines/)还要求披露文中 AI 生成文本。最终投稿须按当时政策处理披露、作者责任和参考文献核验，课程公开会话记录不能替代期刊要求。
