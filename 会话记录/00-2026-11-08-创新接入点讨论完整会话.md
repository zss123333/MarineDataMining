## 四、最小实验怎么做？

### 1. 先做状态判读，不做自由长文生成

准备固定的海洋观测质检案例，例如温盐观测工具的查询结果，要求模型只输出一个状态代码：

| 状态 | 正确解释 |
|---|---|
| 有有效样本、检查通过 | 在指定范围内未发现异常 |
| 有样本、存在异常 | 需要处理异常 |
| 查询合法、无记录 | 无法判断质量 |
| 有记录、覆盖不足 | 证据不足 |
| 参数非法或工具故障 | 执行失败，不能形成质检结论 |

状态代码之后的中文说明由固定模板生成，避免把单 token 探针不加验证地扩展到整段回答。

代码应检查 tokenizer 是否单 token，并平衡或轮换标签映射，防止重复你项目早期出现的格式 token 偏差。

### 2. 设置有意义的对照

所有方案都保留相同的确定性契约检查，再比较剩余案例：

| 方案 | 额外复核的选择方式 |
|---|---|
| 不额外复核 | 基础工作流 |
| 随机门控 | 随机挑选固定比例 |
| 最终输出门控 | 最终概率、熵、同口径候选间隔 |
| 中间层门控 | 最终输出特征＋固定中间层候选支持 |
| 全量复核 | 高成本参考方案，不视为正确性上限 |

**最终层必须加入同口径候选间隔**，避免只是基线特征太弱，造成中间层看似更有效。

### 3. 统一复核动作与预算

例如预先规定只复核 **20%** 的案例；被选中的案例统一执行一次额外证据核对，不能给不同门控方案配不同强度的复核器。

训练、开发、测试应按案例模板或观测场景分组切分，避免只是换几个数字就落入不同集合。层位、探针和阈值都只能在训练／开发阶段选择。

### 4. 主指标别只报 AUROC

优先报告：

- **错误“质量良好”发布率**：把无数据、证据不足或失败误发为质量良好的比例。
- **相同复核预算下的剩余错误率**。
- **正确且获准发布的比例**：防止靠全部拒答获得低错误率。
- **额外延迟与计算成本**：把信号提取和复核成本都算进去。

AUROC、AURC作为辅助诊断。探针分数未经校准时，不能直接称为真实错误概率。

注意：这不是说课程判据错误，而是**在其基础上补充一个设计维度**。

## 原创探索具体在哪里？

### 1. 将“控制权归属”与“控制权授予条件”分开

传统判据讨论：

- 代码决定下一步：Workflow。
- 模型决定下一步：Agent。

你进一步讨论：

- **谁具备提出下一步行动的能力？**
- **当前证据是否足以让它实际决定下一步？**

一个模型可以始终具备规划能力，但应用不必始终允许它自主行动。

这样，“是否使用 Agent”就不再是一次性的架构选择，而是每个关键决策节点上的权限选择。

### 2. 提出“外部证据—内部风险”双维度的自治权授予思路

你的项目可以提供第二个维度，但不能把它当作可靠性的唯一依据：

| 情况 | 建议授予的控制权 |
|---|---|
| 外部证据充分，内部风险较低 | 在预先授权范围内自主选择下一步 |
| 外部证据充分，内部风险较高 | 暂缓执行，进入交叉核验 |
| 外部证据不足，内部风险较低 | 只允许补充证据，不允许下确定结论 |
| 外部证据不足，内部风险较高 | 收回自主权，转固定流程或人工 |

**这里最值得展开的不是“高风险就拦截”，而是：低风险也不能弥补证据缺失。**

内部信号回答的是“模型这次判断可能有多不可靠”；外部证据回答的是“这个判断有没有依据”。二者不能互相替代。

### 3. 区分“允许探索”与“允许落笔”

这是一个能体现你个人思考的进一步改进：

> **不确定性高，不一定应该停止所有行动；它可能应该限制结论与副作用，同时允许低风险的信息收集。**

例如海洋质检助手无法判断某片海域是否异常：

- 可以继续读取观测覆盖、核对时间范围；
- 不可以直接发布“质量良好”；
- 更不可以自行修改正式质控标记。

也就是说，**自治权不是简单的开／关，而应分成查询权、规划权、执行权、发布权。** 同一个不确定状态，对不同权限应产生不同影响。

## 3. 我推荐的创新接入点

### 题目

**《第三次还值得试吗？面向海洋数据处理的进展感知重试预算分配》**

### 核心改进

**将“统一重试3次”改成“硬上限内，按可验证进展续发重试额度”。**

具体不是让模型说“我感觉快成功了”，而是看任务状态有没有真正变化。例如：

| 场景 | 可观察的状态 | 应对思路 |
|---|---|---|
| 下载海洋观测文件遇到限流 | 服务返回等待时间 | 遵守退避策略，不盲目连续重试 |
| 文件解析失败 | 换解析器后，成功读取的变量或时间段增加 | 有进展，可以考虑追加额度 |
| 文件解析失败 | 同一错误重复，始终没有新增有效内容 | 提前停止，预算转给其他文件 |
| 查询海区数据失败 | 区域编码从非法变为合法，但仍无记录 | 已修正参数，接下来检查覆盖范围，而非原样重试 |

**这些状态必须由工具结果或校验器确认，模型自述不算进展。**

### 最值得强调的“新玩法”

不是只决定“继续还是停止”，而是：

> **把提前停下的任务所节省的预算，转给仍在取得进展的任务。**

例如批量处理一批浮标数据文件，不再每份机械地试3次：部分损坏文件提前退出，省下来的额度供那些已经读出部分有效数据、且存在可行恢复路径的文件使用。

这就从**单任务的被动止损**，推进到**整批任务的主动预算再分配**。

## 4. 原创点应该怎样说，才不空泛？

不能只说“我们提出自适应重试”，因为这类思想并不新。值得继续打磨的贡献组合是：

**以可验证的数据处理进展为依据，结合任务自身历史与同类任务的追加尝试收益，在固定总预算内重新分配重试额度。**

它比单纯按错误次数停止，多回答了两个实用问题：

1. **这次失败是否比上次更接近完成？**
2. **下一份预算用在它身上，还是用在别的任务上更划算？**

同时必须保留课程原有底线：总时长、总调用数等硬闸门不取消；不可重试错误不重复执行；有副作用的操作仍受幂等与确认门约束。**预算策略只在允许的行动范围内优化，不越过安全规则。**

## 我的判断

**这个接入点比前两轮更贴合你的要求：课程出处具体，改动对象明确，也能真正改善“预算花在哪里”的实际问题。** 它与 `01-vuc-rl` 的联系是“把能力边界优先的选题思路，迁移为有进展任务优先的重试分配”，而不是研究模型内部机制。

现在可以先围绕这个改进思路推敲，不急着排实验。但还不能称其为已确认的新颖方法：后续需重点对照**自适应重试、进展感知调度和预算分配**，找出这套方案真正新增的能力，而不只是换一个名称。

**3. 对“有效修正”分级，避免把碰巧成功当成因果。**

- 有明确契约依据、错误消失且结果核验通过的，形成可复用修正；
- 原因不明确的，只保留为候选经验；
- 工具版本或数据口径变化后，重新验证，不能永久沿用。
